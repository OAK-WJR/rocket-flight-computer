# R18 gate adversary (Claude)

Target `dcbb6c8`; PCB SHA-256 `632a9ad36c19426ede219b6ff6b0d638955665cac1b4704d3392a6afdbe03982` before and after (verified). **0 Critical / 0 Major / 9 Minor**, all gate gaps demonstrated by seeded faults on probe copies; R18-GATE-01 also names current-board geometry. No canonical edit, build, git state change or canonical check.sh. Probe material: ignored `.supervisor/r18_gate/`.

## Method

Every seed is an APFS clone of a full working-tree copy (fab zip and PDFs included, peer round-18 reports removed). One fault is applied with KiCad 10.0.7 pcbnew (zones refilled) or a text edit. Board seeds then get the regeneration a developer or `m3_design/r10_build.sh` runs after the board (budget, hot-plug extract + NumPy solve, `jlc_orient`, `export_fab`, the three `r10_fab.sh` validators, binding note), replicated with explicit copy paths because `r10_fab.sh` changes to the git top level. Then the exact check.sh checker commands run one by one: DRC (all severities, parity), ERC, `verify_board`, `silk_check`, `r10_parts --check`, `fit_check`, full `check_r10`, `route_check`, `fab_manifest`. Seeds a content rule already rejects ran focused (hash-bound F9-1 / K-binding staleness ignored). Three controls (unmodified, regeneration only, load/refill/save) pass every stage, and regeneration reproduces hot-plug, budget, binding, BOM and CPL byte for byte. The complete check.sh, self-tests included, exits 0 on the R18-GATE-01 and R18-GATE-02 seeded copies.

## Findings

**R18-GATE-01 (Minor, new) — S-8 does not protect the load-switch gate barrels: ACT_GATE vias sit 0.251 mm from In1 GND (the turn-on direction) and a 3V3 plane re-cut beside them passes the complete gate.** BARREL_NETS (`tools/check_r10.py:867`) holds RAW_ACT / IGN / OUT / PYRO1_GATE and every barrel exempts GND (`:1592`), N-side semantics. Q120/Q121 are P-FETs: an ACT_GATE short to GND is at or below the designed on-state gate (about 0.09 x V_S), and to 3V3 gives VGS about -3.4 V against AONR21357's -2.3 V maximum threshold (AOS Rev 2.1 p. 2). On the current board both ACT_GATE vias, (16.2, 73.3) and (11.8, 70.725), are 0.251 mm from In1 GND; neither the current deviation inventory nor the historical round-10 row (which names only the benign In2 RAW_PROTECTED neighbour, at stale coordinates) records that adjacency. Seed `s04_actgate_3v3` re-cuts In2 so 3V3 sits 0.251 mm from the (16.2, 73.3) barrel; it passes all eight check.sh checker stages after full regeneration, and the complete check.sh (shell 7, fit 31, paste 16, parts 5, route 67, R10 180 with 4 NumPy skips, hot-plug 2) exits 0. One inner defect therefore enables the pyro bus with PC1 low; PE4 still controls firing and a static short shows in the cold screen.

**R18-GATE-02 (Minor, new) — K-width only counts tracks at exactly the 0.3 mm floor: the U9 output path (0.7 -> 0.31 mm) and the U9 input feed upstream of C88 (1.0 -> 0.31 mm) pass the complete gate.** K-width joins a segment to a 'narrow run' only when it is <= 0.301 mm (`tools/check_r10.py:2608`). Seed `s03_rawprot_neck` narrows the six 0.7 mm U9-output runs (8.414 mm, 3.628 mm in series with the whole load) to 0.31 mm: all regeneration and all checker stages pass, K-width's evidence is byte-identical to the baseline, and the complete check.sh exits 0. tools/ipc2152.py (Inference, upper bound): 74.0 vs 29.0 C at 2.9 A, 137.0 vs 53.7 C at U9's calculated 3.946 A minimum limit. On the U9 input side only the C88 -> U9 local-path bound in F9-1 and a route_check bump redraw catch narrowing incidentally (`s03b`); `s03c` (upstream of C88 only) also passes every stage. No other power rail has any width floor.

**R18-GATE-03 (Minor, new) — Current-carrying layer transitions and the fire-current GND return have no gate: the U9 output reaches In2 through one 0.3 mm via and the gate still passes.** No rule counts or sizes power-path vias or the fire-current GND return. `s11` removes one of the two U9 OUT -> In2 vias (all board power then crosses one 0.3 mm barrel) and passes every stage; `s11b` shrinks the only U9-feed via (17.5, 87.3) from 1.0/0.5 to 0.5/0.3 mm and passes every stage (the hot-plug model still qualifies); `s26` narrows Q124's 0.3 mm source bar and via stubs to 0.15 mm (D-R3-03's 16 C at 4.2 A / 20 ms becomes about 64 C, adiabatic Inference) and passes every stage.

**R18-GATE-04 (Minor, new) — check.sh never validates fabrication content, and export_fab.py binds the manifest before r10_fab.sh validates: a reversed D9 placement and a substituted R134 BOM code both pass.** `export_fab.py:179` writes the manifest; `r10_fab.sh:32-39` then runs S-4 --bom/--cpl, --verify-cpl and paste_check, so a validator failure leaves a valid manifest, and AGENTS.md section 5 documents `python3 tools/export_fab.py` alone. check.sh (`:56-66`) verifies hashes only. `s17` gives D9 (B340A) a stale +180 deg correction and runs export_fab only: the CPL places D9 reversed (90 -> 270 deg), all eight stages pass, and only --verify-cpl fails (residual 4.193 mm). `s18` swaps R134's BOM code C3013496 -> C25744 and refreshes the manifest: the gate passes, S-4 --bom fails.

**R18-GATE-05 (Minor, new) — Canonical fab-package enforcement keys on a literal path string and an unowned skip flag.** check.sh recognises the repository board by string equality. On the stale-fab copy `s19` (silkscreen nudged, package not re-exported) the canonical spelling fails as intended, but the same file spelled `.../M3_DESIGN/assembly_review/m3.kicad_pcb` (same inode on the case-insensitive volume) prints 'not checked (board copy)' and every stage exits 0, and `R10_SKIP_FAB_MANIFEST=1` exits 0 too although `r10_build.sh` no longer sets it (D-R8-03 still says it does).

**R18-GATE-06 (Minor, new) — K-rules does not pin the silkscreen text floors: a 0.6 mm safety designator passes after the project floor is lowered.** PRO_FLOORS (`tools/check_r10.py:812`) omits min_text_height / min_text_thickness / min_silk_clearance, and no checker reads text size. `s23` lowers the project floors to 0.5 / 0.08 mm and shrinks the shown safety designator R134 to 0.6 mm / 0.10 mm: all regeneration and all eight stages pass.

**R18-GATE-07 (Minor, new) — The five support coordinates of P1 / P2 / VEHICLE.md are not pinned: a 2.55 mm support move passes.** M-3 counts five Edge.Cuts circles and fit_check allows each corner support anywhere within 6 mm and the fifth anywhere in the middle third, although P1 / P2 and VEHICLE.md fix the sled holes. A 3 mm move to (4, 47.3) is caught only by part clearances, but 208 fit-clean moves exist; `s15b` moves (4, 44.3) to (3.5, 46.8), 2.55 mm, and passes every stage.

**R18-GATE-08 (Minor, new) — Terminal word legends have no blocking subject association: BAT can head the igniter terminal and IGN the battery terminal.** Word legends are judged only by the AUD-10 review-only distance and SWITCH is not in WORD_LEGENDS_R10. `s16` exchanges BAT and SWITCH (pin legends unchanged): K-legends passes with one review entry ('BAT' 10.0 mm from J1); its full run is caught only because the longer SWITCH text then leaves the board. `s16c` exchanges BAT and IGN, so the black igniter terminal is headed BAT and the battery terminal IGN, and passes every stage after full regeneration.

**R18-GATE-09 (Minor, new) — Non-generated safety lands are not pinned: a consistent library + board edit of Q124's gate pad passes.** Only the nine r10_parts-generated footprints are geometry-pinned; DRC's library comparison passes when the library and board change together. `s25` moves Q124's gate pad 0.08 mm in `kilib/rocket.pretty/M3_AON7524_DFN3x3A.kicad_mod` and in the placed part: regeneration (verify-cpl residual unchanged at 0.491 mm) and all eight stages pass.

## Limits

- No canonical-tree edit, build, git state change or canonical check.sh. Two complete check.sh runs (self-tests included) were made on seeded probe copies only.
- m3_design/r10_build.sh and r10_fab.sh were not executed (they cd to the git top level, i.e. the canonical tree); their post-board steps were replicated with explicit probe paths. Generator stages before r10_post (r10_sch.py, r10_pcb.py, r10_route.py) were not exercised: seeds are post-generation board edits.
- kicad-cli / pcbnew 10.0.7 throughout; the installed 10.0.6 was not used. Zone refills by 10.0.7 differ from the saved 10.0.6 fill by a few vertices; the save control (s02) passes every stage, so this does not mask or create a finding.
- Temperatures are IPC-2152 curve-fit upper bounds (Inference), not measurements; currents are the project calculations cited. Seeded misses are prospective gate gaps unless stated as current board geometry.
- Other lenses (safety, power, routing, ...) were not read (independence rule); overlap with them is possible.
- No physical, firmware, supplier or JLC process check. Maker datasheet values are from the cached AOS PDF (Rev 2.1), cited by its maker URL.
