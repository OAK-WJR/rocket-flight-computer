The owner's decisions for M3-ASSY-R8, taken on the owner's behalf from the agreed plan (`r8_plan.md`, Strategy B), the
surveys, `docs/REQUIREMENTS.md`, `AGENTS.md` and the parent `CLAUDE.md` / `docs/VEHICLE.md`. Each entry gives the
decision, its basis and the fallback agreed now. Later steps add their decisions below the step-0 block (D-numbers
continue).

- **Board baseline:** R7, commit 431025d, `m3.kicad_pcb` SHA-256 `c872a3d3…` (re-hashed in this step).
- **Coordinates:** KiCad mm; y = 0 is the aft edge (SMA jacks), y = 118 the forward edge (J1); "forward" is +y.
- **Pin contract:** `pin_table.tsv` (this folder) is the full R8 U1 pin map, 100 rows, every row cited. It is
  generated by `step0/make_table.py` (reproduce: handoff `r8_step0_handoff.md`).
- **Inference** marks anything not taken from a maker document or measured (AGENTS §2.5).

## D1. U1 rotation

**Decision:** U1 at KiCad rotation 0, top side, at the seed position (23.0, 45.0) (`partial/b0_place_final.tsv`).

- Checked in pcbnew on the R7 footprint: at rotation 0, pin 1 sits at (−6.0, +7.55) and pin 25 at (+6.0, +7.55); pin 26 at (+7.55, +6.0); pin 51 at (+6.0, −7.55); pin 76 at (−7.55, −6.0).
- So pins 1–25 face forward (west to east), pins 26–50 face east (forward to aft), pins 51–75 face aft toward the RF
  strip (east to west), and pins 76–100 face west (aft to forward).

**Basis:**
- `r8_plan.md` §1 and `plan_partial.md` §3: with D2's map and blocks re-homed, the radio and GNSS lanes leave U1 in
  module order.
- No requirement fixes U1's position or rotation (survey_constraints §9). The pin contract is set by pins, not by
  geometry.
- The part is square and 1.4 mm tall, so P2 fit is unchanged. The JLC CPL rotation correction is per footprint
  (survey_constraints §13), so it still applies.

**IOSWP (RM0433 Rev 9, verified).**
- §50.11.4 (p. 2222) defines SPI_CFG2 bit 15 IOSWP: "When this bit is set, the function of MISO and MOSI pins
  alternate functions are inverted". The register resets to 0 and is write-protected while the SPI is enabled.
- §50.4.2 (p. 2159) and the note in §50.4.4 (p. 2161) state that it works in every SPI mode.
- Table 422 (p. 2157) lists no instance that lacks it. The local CMSIS header defines `SPI_CFG2_IOSWP` (bit 15),
  which agrees.
- The plan's "+2 vias without IOSWP" fallback is therefore not expected to be needed.

**Reset and bootloader states (radio held in reset; uplink cannot arm).**
- **In reset:** every GPIO is analog and high-Z (DS12110 §3.8, p. 32; Table 8, p. 63). Each line is then set by its
  external part, all unchanged in value:
  - R311 (2.0 kΩ) pulls RADIO_NRST low on PE9, so the SX1262 is held in reset and cannot transmit.
  - R312 (100 kΩ) pulls RADIO_RXEN low.
  - R310 (100 kΩ, now to 3V3 at the MCU end, D4) pulls RADIO_NSS high, so the SX1262's MISO is high-Z.
  - SX1262 DIO1 is pulled down and BUSY pulled up in reset (`pass2_electrical.md` §3.2).
- **PE9, PD9, PE15, PD14, PD15, PE7 and PE8** do not appear in AN2606 Table 135 (pp. 320–323). The bootloader
  leaves them alone.
- **PB11 (RADIO_NSS)** is the bootloader's USART3_RX: an input with pull-up (Table 135, p. 321). With R310 the line
  idles high, so 0x7F never arrives and USART3 is never selected.
- **PB10 (RADIO_SCK)** is USART3_TX.
  - On bootloader V9.1 (0x91) it stays an input until USART3 is detected (p. 321), which cannot happen.
  - On an older bootloader it may drive idle-high. That goes into the SCK input of an SX1262 held in reset: no
    contention and no effect.
- **PB14 (RADIO_MOSI)** is USART1_TX on the PB14/PB15 map: an AF push-pull output with pull-up, with no
  "input until detected" note (p. 320). On V9.1 it also echoes PA9's USART1 data (Table 136, p. 326), and PA9/PA10
  stay unconnected. It drives only the SX1262's MOSI input, and the SX1262 is held in reset. This is better than R7,
  which had the SX1262's high-Z MISO output on this pin.
- **PB15 (RADIO_MISO)** is USART1_RX, an input with pull-up (p. 320). The SX1262's MISO is high-Z, so the pin idles
  high. It is never at GND, which keeps clear of the Table 136 limitation that "If PB15 is set to GND, user cannot
  connect to BL interfaces" (pp. 325–326).
- **No AF path to a pyro, arming or servo pin:**

  | Peripheral | Alternate pins on LQFP100 (DS12110 Table 10, pp. 89–94) | Status |
  |---|---|---|
  | SPI2 | PA9, PA11, PA12, PB4 (NSS AF7), PB9, PB12–PB15, PB10, PC1, PD3; PC2_C/PC3_C only with the SYSCFG analog switch closed (Table 9 note 4, p. 88) | PC1 is a sentinel and stays NC; PC2_C/PC3_C are the VLOGIC/V3V3 supply senses, not safety pins; PD3 is now NC |
  | UART7 | PA8, PA15, PB3, PB4, PE7–PE10 | none is a pyro, arming or servo pin |
  | TIM4 | PB6–PB9, PD12–PD15, PE0 (ETR) | none is a pyro, arming or servo pin |
  | USART6 | PC6–PC8 | none is a pyro, arming or servo pin |

  The pyro gate PE4, the senses PC0/PC5/PB0 and the servos PA0–PA3 carry none of these functions.
- **No RF net touches a safety net.** R310's pins are RADIO_NSS and 3V3, neither of which is a safety net
  (`check_r7` SAFETY_NETS). The uplink therefore still cannot arm or fire (F10).

**Exceptions to the frozen design §3.10** (`docs/ROCKET_FC_FROZEN_DESIGN.md`, "Reserved / explicitly forbidden"):
- **PB10/PB11 "Avoid" (ROM USART3).** Granted. The argument is the one R7 pass 2 accepted for PB14/PB15: NSS is held
  high, so USART3 is never detected; the radio is held in reset; and SCK and MOSI drive inputs only. This is the
  plan's named PB10/PB11 exception (`r8_plan.md` §3 step 0).
- **PE9 "Forbidden: TT_ha" (DS12110 Table 9, p. 72).** Granted for an on-board line.
  - The frozen reason is the 4.0 V TT limit (Table 11, p. 103), written for off-board and servo use (the TIM1 servo
    scheme).
  - RADIO_NRST joins only PE9, R311 to GND and the SX1262's NRESET on 3V3_RADIO, so it never exceeds 3V3.
  - PE9 sources 1.65 mA into R311 to release the radio (3.3 V / 2.0 kΩ), as PD9 did in R7.
  - R7 already uses TT_ha pins PE7/PE8 on board.
- **PD8/PD9 "Keep free" (H723 FDCAN).** Already voided by R7 pass 1 (`pass1_electrical.md` §5).

**Fallbacks (agreed now):**
- **No IOSWP:** RADIO_MOSI_MCU returns to PB15 (54) and RADIO_MISO_MCU to PB14 (53), as R7 had them. The two lanes
  then cross once: +2 vias, each with its GND via.
- **PB10/PB11 exception refused, or spike 3(d) fails:** map **H1′**, the connectivity survey's H1 with NRST on PE9
  instead of PE7, because PE7/PE8 now carry UART7.
  - SCK PB13 (52), NSS PB12 (51), MOSI PB14 / MISO PB15 with IOSWP, BUSY PD8, RXEN PD9, NRST PE9, DIO1 PE15.
  - GNSS as H0. PB10/PB11 stay NC.
  - Cost: one NSS × SCK crossing, a via pair with GND vias. The model gives 14 crossings instead of 13
    (`step0/final.py`).
- The camera stays on UART7 in every case. This removes R7's path for a camera to capture the DFU bootloader through
  USART3.

PD2, PE13, PE14, PA15.

**Loader and reset states of the moved pins** (AN2606 Table 135; DS12110 §3.8):
- **PA4/PA5/PA7** are the bootloader's SPI1 NSS/SCK/MOSI, slave inputs with no pull (p. 322).
  - BAT_FAULT_N (R89 to 3V3) holds NSS high, so the SPI1 slave is deselected.
  - CAM_UART_OE (R102 to GND) holds MOSI low, so the slave could never receive the synchronisation byte.
  - PA6 (MISO, driven) stays NC.
  - The frozen "no signal that matters at reset" rule holds: two status inputs, and an enable that its pull-down
    keeps low.
- **PE11/PE12** are the bootloader's SPI4 NSS/SCK inputs (p. 323).
  - CAM_FAULT_N (R76 to 3V3) holds NSS high (deselected).
  - CAM_PWR_EN (R75 10 kΩ to GND through R74) holds SCK low and the camera eFuse off.
  - PE13 (MISO, driven) and PE14 stay NC.
  - This is an exception to the frozen "Avoid PE11–PE14", granted on that argument. The pins are used as GPIO only,
    and SPI4 is never enabled (R7 pass 1 E2: SPI4_NSS is also AF5 on PE4, the pyro gate).
- **PC13, PD5, PD7 and PC8** are not bootloader pins.
- **In reset:** BUZZ_DRV is low (R163), CAM_UART_OE low (R102), CAM_PWR_EN low (R75), and the LEDs are off (LED to
  GND). The status inputs follow their pull-ups.
- **TT and injection:**
  - PA4 (TT_a), PA5 (TT_ha), PA7 (TT_a) and PE7/PE8 (TT_ha) carry only on-board lines pulled to 3V3 or GND, or U12's
    3V3 A side.
  - U12 TXU0202's VCCA is 3V3 (netlist). That its A-port outputs stay at or below VCCA is an **Inference** from the
    translator's two-rail design; the TI datasheet was not re-read here.
  - PA4/PA5 have IINJ 0/0 mA (DS12110 Table 49, p. 136): inputs only, pulled to 3V3, with no path to inject.
- **PC13 output drive:** VOH ≥ VDD − 0.4 V at 3 mA (Table 52, p. 140), at most 2 MHz. BUZZ_DRV drives Q123's gate
  through R162 (220 Ω) against R163 (10 kΩ). The DC load is 0.33 mA, and the buzzer tone is about 2.7 kHz (corrected in
  D79: 4.0 ± 0.2 kHz, Huaneng datasheet).

**Placement consequence (step 4):** LED1/LED2 (with R32/R33) move from the seed's east column to the west edge, top
side, at about x 5–8, y 44–52 (above U4/U5, which are on the bottom). LED_RED goes aft of LED_YEL, to match pins
86/88.
- LED2 is a 5 mm tab-rule item, so its tab windows are re-scanned.
- **Fallback, if the west edge has no legal room:** LEDs on PA6 (LED_YEL; loader-driven, so an LED may flicker in the
  bootloader) and PA7 (LED_RED), with CAM_UART_OE on PE14, east as in the seed. The model gives 17 crossings.

## D4. R310 rail

**Decision:** R310 (100 kΩ) pulls RADIO_NSS to **3V3**, not 3V3_RADIO, and sits at the MCU end of the NSS lane.

- Placement:
  - R310 counts as an RF part (`check_r7` RF_PART), so it stays ≥ 5 mm from U1's courtyard (F10).
  - Like R313/R315, it sits on the lane nearer U1 than U31.
- Contract change for `check_r8`: PULLS gets `('R310', 'RADIO_NSS', '3V3', '100k')`.

**Basis:**
- `r8_plan.md` §1 ("R310 at the MCU end on 3V3"); `plan_cleansheet.md` O-4(a).
- 3V3_RADIO is 3V3 through FB31 alone (netlist: FB31.1 on 3V3, FB31.2 on 3V3_RADIO) with no switch, so NSS sees the
  same rail to within FB31's drop. That drop is a few mV (**Inference**).
- The pull-up also holds PB11 (the bootloader's USART3_RX) idle-high, which is the D2 argument.
- It removes the NSS tap via inside the strip and the 3V3_RADIO B.Cu hop. `check_r8`'s STRIP_B and STRIP_VIA lose
  RADIO_NSS, and RADIO_DIO1 too (H0 brings DIO1 in on F.Cu). RADIO_TXEN stays.

**Fallback:** keep the 3V3_RADIO rail with a 2-via B.Cu hop, which F10 allows as "each module's own supply".

## D5. Pins the ROM bootloader drives

The rule for step 1's reset and loader check: a pin that AN2606 Table 135 configures as an output or as open-drain
I/O may carry only the nets below. Every other such pin stays NC.

| Pin | Net | Why it is allowed |
|---|---|---|
| PA2 | SERVO3_MCU | frozen §3.2: an input until detected on V9.1, and a servo never sends 0x7F (R7 pass 3 §4.4) |
| PB10 | RADIO_SCK_MCU | D2 |
| PB14 | RADIO_MOSI_MCU | D2 |
| PA11 / PA12 | USB_DM / USB_DP | DFU is the bootloader interface itself |
| PB6 | QSPI_NCS | open drain only; the 10 kΩ pull-up keeps the flash deselected (frozen §3.5) |
| PB9 | I2C1_SDA | open drain, with its 4.7 kΩ pull-up (frozen §3.6) |
| any | an LED | an LED that flickers in the bootloader is harmless |

R8 puts no LED on a bootloader pin.

Must stay NC: PA6, PA8, PA9, PA10, PC9, PC11 and PE13. `pin_table.tsv` column `loader_driven_allowance` carries these
reasons, and the generator asserts them.

## D6. EXTI map and firmware-binding constraints (R8)

**EXTI lines.** SYSCFG_EXTICR selects one port per line (RM0433 §12.3.2–12.3.5, pp. 552–555).

| Line | Signal | Notes |
|---|---|---|
| 4 | BAT_FAULT_N (PA4) | |
| 5 | LOGIC_SOURCE_ST (PA5) | EXTI9_5 vector |
| 6 | USB_FAULT_N (PD6) | EXTI9_5 vector |
| 8 | VBUS_SENSE (PC8) | EXTI9_5 vector. BUSY (PD8) is on the same line, so BUSY is polled |
| 11 | CAM_FAULT_N (PE11) | EXTI15_10 vector |
| 14 | PULLPIN (PC14) | EXTI15_10 vector |
| 15 | RADIO_DIO1 (PE15) | EXTI15_10 vector |

- The EXTI9_5 and EXTI15_10 handlers check each pending bit (vectors: RM0433 Table 147, pp. 754–755).
- TIMEPULSE is read by TIM4_CH4 capture on PD15, never EXTI15.
- IMU_INT1 (PE1) stays polled.

**Binding constraints:**
1. Write SPI2 SPI_CFG2.IOSWP = 1 while SPE = 0, before PB14/PB15 are switched to AF5. Never assert NSS before that.
   NSS is software-driven (PB11 GPIO).
2. Radio start order as in `pass1_electrical.md` §5.4 (M3_R7 pin contract): NSS high, RXEN low, then release NRST
   (PE9 high) and wait for BUSY low.
3. Never select AF7 (UART7_RTS/DE) on PE9 or UART7_CTS on PE10. UART7 runs without flow control. PE10 stays NC.
4. PE4 is locked (GPIOE_LCKR) before any other GPIOE set-up. SPI4 is never enabled; PE11/PE12 are GPIO only.
5. Never route RTC_OUT, ALARM, CALIB, TAMP or TS to PC13 (backup domain; BUZZ_DRV). The pin is limited to 2 MHz.
6. PA4/PA5/PA7 are GPIO with internal pulls off (external pulls exist), and are not used by the ADC.
7. Keep CAM_UART_OE (PA7) low until the camera is powered and UART7 is set up.
8. (Fix pass 1, R8P1-REQUIREMENTS-02.) Before any jump to the ROM bootloader, put the SX1262 to sleep, drive PE9
   (RADIO_NRST) low, then return PE9 to analog mode (or reset GPIOE through RCC_AHB4RSTR), so R311 holds NRST low in
   the bootloader. BOOT0 (U1.94) has only R5 to GND and is not on J2 (J2.6 NC), so AN2606 Rev 70 Table 2's BOOT0 = 1
   pattern cannot be selected and a firmware jump (USB DFU, ORDERING section 5) is the only way in; AN2606 Table 135
   configures only the bootloader's own interface pins, so PE9 would otherwise keep its last application state
   (Inference). NSS stays high through R310 either way, so the loader-capture safety of D2 / D5 does not depend on this
   step; F10's "cannot transmit in the bootloader" does. (Fix pass 2, R8P2-PYRO-03.) PE4 (PYRO1_GATE_N) is driven low
   first: the bootloader leaves PE4 in its last application state like PE9, and constraint 4's GPIOE_LCKR freezes PE4's
   configuration registers, not its output data (RM0433 §11.4.8, GPIOx_LCKR): a jump made with PE4 high would hold an
   armed gate on for as long as the bootloader runs, outside the application's 20 ms fire limit (Inference).
   (Fix pass 3, R8P3-RF-01: fix pass 2 allowed the GPIOE reset as the first step, which returns PE9 to analog before the
   radio is put to sleep; R311 then asserts NRST, the SX1262 holds BUSY high in reset, and a driver that waits for BUSY
   low before SetSleep hangs, so the jump is never made. Fail-safe, but self-contradictory.) **The order is:** (1) drive
   PE4 low; (2) put the SX1262 to sleep and drive PE9 low; (3) last, reset GPIOE through RCC_AHB4RSTR, which clears the
   lock and returns PE4 and PE9 to analog, so R127 holds the gate off and R311 holds NRST low in the bootloader (without
   the reset: keep PE4 driven low and return PE9 to analog). Never reset GPIOE before step 2. Bench check: ORDERING §5's
   pyro-gate list, its "Bootloader" step (repeated after any firmware change with the rest of the list): PYRO1_GATE at
   TP122 below 0.1 V after the jump with the ARM link out, the board confirmed still in the bootloader once USB is
   unplugged, then the static pyro gate armed there (R8P3-REQUIREMENTS-01; moved from the RF bullet's bootloader repeat
   of the radio-reset step, which now points to it, after review pass 4, R8P4-REQUIREMENTS-01).

## D10. Detour baseline

**Decision:** route_check's detour test (M2: copper > 1.6 × the octilinear MST of the pad centres and > 2 mm longer)
keeps its thresholds. For a net whose straight MST edge crosses a **hard keep-out**, that edge's baseline length
becomes the shortest octilinear path that avoids the keep-out.

A hard keep-out is any of:
- an area where every copper layer the net can use is closed to tracks (the layer intersection of rule-area
  keep-outs);
- the U31 body for every non-GND net (F10: "Nothing but GND crosses U31's pad field on any layer");
- an NPTH hole or the board edge.

**Scope limits:**
- Parts, pads, other nets' copper and soft keep-outs are never obstacles, so congestion detours stay failures.
- Every net judged on the refined baseline is listed with both ratios.
- All other nets keep the plain baseline.

**Basis:**
- `r8_plan.md` §1 ("keep-out-aware detour baseline", from C, `plan_cleansheet.md` §7 item 1(a), O-6).
- M2's intent is "no needless detours". A path no legal copper can take is not a needless detour, so this is an
  implementation detail and does not weaken the test.
- It turns R7's RADIO_TXEN entry (25.2 mm against a 10.9 mm MST that crosses the module) from an allowlist entry into
  a measured pass.
- REQUIREMENTS M2 text updated (R8 mark).
- Step 1 adds a seeded test: a detour beside the keep-out must still fail.

**Fallback:** if step 1 cannot make the refinement exact, RADIO_TXEN carries one allowlist entry with its measured
reason (`r8_plan.md` §2 lists TXEN and A8 as the accepted inherent items).

## D12. 7.7 A necks and the ACT_FET_S rise threshold

**Method:** IPC-2152 fit (Brooks & Adam) with no plane credit. This is the survey's `dc_neck.py` and `scorecard.py`
for 35 µm outer and 30 µm inner copper at 7.7 A.

| Neck | R7 | R8 requirement | Expected rise at the requirement (upper bound) |
|---|---|---|---|
| RAW_ACT | 3.00 mm, 38 °C | ΔT ≤ 20 °C at the neck's layer: ≥ 5.3 mm outer (5.28) or ≥ 5.6 mm inner (5.56); path R ≤ 3.7 mΩ (survey target) | ≤ 20 °C |
| BAT_IN | 3.82 mm (In2), 30 °C | same 20 °C rule: ≥ 5.6 mm inner or ≥ 5.3 mm outer; path R ≤ 3.0 mΩ (survey target) | ≤ 20 °C |
| ACT_FET_S | 2.65 mm (B.Cu), 44 °C | **ΔT ≤ 30 °C: ≥ 3.71 mm on B.Cu** (target 4.35 mm, 25 °C) | 24–29 °C expected (3.8–4.5 mm); 32 °C at 3.5 mm |

**Expected rise.** The AON6403 source row (pins 1–3) spans 3.12 mm (R7 footprint), with the gate pad 0.69 mm beyond
pin 3, edge to edge.
- Facing the two FETs' source rows, offset along the row so that neither gate pad lies inside the bridge, gives about
  3.8–4.5 mm of B.Cu bridge (**Inference**, geometry).
- That is a 24–29 °C rise by the fit, about half with In1 plane credit (**Inference**, M3_R7).
- At the 70 °C bay maximum, copper stays near 100 °C at the 4-servo stall, well inside the FR-4 laminate and solder
  limits (**Inference**).

**Basis:**
- `r8_plan.md` §2 asks for an "owner threshold (pad-limited)" for ACT_FET_S, agreed in step 0.
- 30 °C equals R7's accepted BAT_IN rise and is 14 °C better than R7's accepted 44 °C ACT_FET_S rise.
- A short bridge between two pad rows is conductively cooled by the FET bodies, so the long-trace fit overstates it.

**If missed:** a measured miss between 30 and 44 °C is a recorded deviation for the owner, with its cause. Above 44 °C
(R7's accepted value) is a regression and a Major review finding. REQUIREMENTS F4 is updated (R8 mark).

## D16. Strip fence rule

GND vias on FENCE_Y (23.3) are at most FENCE_PITCH (2.0 mm) apart, the board's side edges counting as ends. A wider
gap is an opening only if at least one non-GND track crosses FENCE_Y inside it, and it is at most 2.7 mm wide.

## D24. The schematic transform

- **Source of truth.** `r8_sch.py` reads `pin_table.tsv` at run time: every row whose `r8_net` differs from its `r7_net`
  (27 pins: 13 reassigned, 7 moved in, 7 freed), plus R310.1 3V3_RADIO → 3V3 (D4). It asserts the table first (pins
  1–100, the `change` column, the D14 contract pins unchanged, no new net on U1).
- **Edits, all on the MCU sheet** (every U1 pin there is a short wire and a global label, or a no-connect flag; no other
  sheet names a U1 pin):
  - a pin that keeps a net gets the new label text in place (same wire, position and UUID);
  - a freed pin loses its wire and label and gets a no-connect flag;
  - a moved-in pin loses its flag and gets a 5.08 mm wire and a global label, as R7's pins have.
- **Label shape.** A moved net keeps the shape its R7 label had on the MCU sheet (BAT_FAULT_N and LOGIC_SOURCE_ST
  `input`, the rest `passive`), so each net's label looks the same wherever it sits.

  RF pin note), telemetry (GNSS, radio, reset and loader), camera UART, USB sense, pull-pin and buzzer. New notes on the
  MCU sheet give the follow-on moves (D3) and the loader-pin rule (D5). The servo sheet records D7.

## D27. Buzzer drive on PC13

## D74. Absolute critical-reference metric

**Tool.** `tools/reference_audit.py BOARD [--extended]` samples the board's own critical tracks exactly as
`critical_reference.py` does (its unreferenced count equals `critical_reference.py BOARD BOARD`, which the scorecard's
R6b divides by the sample count; asserted in `tools/test_reference_audit.py`) and classifies each unreferenced sample by
what lies on the reference layer: a fill-keep-out rule area, another net's fill, its own via's antipad (≤ 0.7 mm from a
same-net via or plated pad, the survey's OWN_VIA), another via's antipad (≤ 0.5 mm beyond its copper), another net's
track, a fill edge (a split), or a void. Tests: the count matches critical_reference; each cause is named at a seeded
point; a seeded B.Cu QSPI_CLK track over the RAW_ACT In2 island adds exactly its samples, all "over_fill".

**Result on `429b6db4…`.** R6 set: 47,769 samples, 5,525 unreferenced (11.57 %): own via antipads 3,589, the crystal's
`Y1_In2_keepout` 1,710 (HSE_IN / HSE_OUT on B.Cu under Y1, R5 V1's deliberate keep-out, In1 GND above), other vias'
antipads 226 (track edges passing a neighbour's antipad); **none over another net's fill, along a split or over a void.**
Extended set: 103,308 / 6,283 (6.08 %), the same three causes. R7 with the same tool: 27.91 %, of which 11,516 samples
under another net's track, along a split, over a void or over a foreign fill.

**Decision.** R6b (0.1157 against the plan's ≤ 0.08) stays a measured miss on the deviation list with this cause. The
plan's "no cause measured yet" is closed. Removing the own-via share means fewer layer changes on critical nets (already
25, each with its GND via), and the keep-out share means dropping R5 V1's crystal rule: neither is a defect, and both
would trade a priority-1 property (layer assignment, crystal loading) for a metric. Recommended for the scorecard (not
done here: the plan's targets are not this step's to change): count the "over another fill, split or void" share, which
